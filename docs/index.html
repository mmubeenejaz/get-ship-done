Get Ship Done

by Mubeen

A Claude Code plugin that takes one requirement to a draft pull request: the right amount of ceremony for the change, unambiguous task cards, test-first building, the project's own gate, and a cold review where it pays.

How a run flows

Lanes

LaneWhenDocumentsApprovalsReview
DirectUnder about 50 lines, no open decision, nothing riskyNoneThe diffSelf-review
StandardOne PR, nothing riskyOne brief (spec and plan together)1Self-review, plus a cold review when the session runs below Opus
RiskyAuth, permissions, tenant isolation, migrations, money, personal data, security, over about 400 lines, or several PRsSpec, then plan2Self-review plus a cold review

Task cards: clear enough for a smaller model

Every brief and plan ends in task cards. A card is written so a builder that has read nothing else can do it right. Its level picks the builder: mechanical for Haiku, standard for Sonnet, judgment stays with the orchestrator.

### T2  Keep containers on unknown run state        level: mechanical
Files:      e2e/ci-doctor.mjs (modify)
Pattern:    copy doctorSteps() shape, e2e/ci-doctor.mjs:21
Interface:  doctorSteps(state) -> [{action:'keep'|'remove', name, runId}]
Test first: e2e/housekeeping.test.ts "keeps a container when the run status cannot be read"
Done when:  pnpm exec vitest run e2e/housekeeping.test.ts -> 10 passed
Don't:      change the start-runner or start-docker paths
Stop if:    the test passes before the change

What keeps quality up

Prove the tests

Break the code behind the key criteria, watch the test fail, restore it. A test that stays green is rewritten.

Cold review

A fresh reviewer with read-only tools, on the session's own model, sees only the brief and the diff.

Lessons

A review finding a machine can detect becomes a check whose error names the fix. Only judgment calls stay as checklist lines.

UI with a direction

A UI brief starts from five lines of product direction. Generic tokens are flagged on new lines, and gsd ui-audit triages existing screens before an unslop.

Check routing

Tests are picked from the change through the project's selector, never the full suite until the gate.

Session management

A new session or subagent costs roughly 65k tokens before it does any work, and long sessions get expensive to continue. So the orchestrator measures its context at each checkpoint (brief approved, PR shipped, gate started), hands off to a fresh session above about 200k tokens or after a compaction, and in Risky work gives each PR's cards to one build session on the cheapest model they allow. Subagents are used only for a read-heavy sweep, the cold review, or large independent work.

Install

claude plugin marketplace add mmubeenejaz/get-ship-done
claude plugin install get-ship-done@get-ship-done

Run it with /get-ship-done:ship <requirement>. Then add a ## Get Ship Done section to the project's AGENTS.md naming its gate, test selector, pre-check and PR facts commands; without one, the skill finds the gate in the CI config and offers to add it.
